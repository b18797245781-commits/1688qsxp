# 页面一比一还原技能

## 目标

将用户提供的网页、HTML快照或页面资源还原为可直接打开的离线页面。优先保持原始HTML结构、CSS样式、布局尺寸、图片、字体、图标和文字，不主动重做UI，不引入新框架。

## 必须遵循的处理流程

1. **确认输入和输出**
   - 找到用户提供的HTML文件及其同名资源目录。
   - 输出到用户指定的工作目录，HTML与资源目录保持相对位置。
   - 编辑前先读取当前文件，识别用户已经确认正常的修改，避免覆盖已有有效修复。

2. **资源本地化**
   - 扫描HTML、CSS和内嵌样式中的`src`、`href`、`url(...)`引用。
   - 优先使用已有本地资源；只下载明确缺失的图片、CSS、JS和字体。
   - 保持原始文件名和目录结构，避免批量重命名导致引用失效。
   - 处理字体时重点检查`@font-face`：`element-icons`、`iconfont`以及其他自定义字体必须本地存在。
   - CSS中的字体路径必须相对于CSS文件所在目录，例如资源目录内CSS引用项目根目录字体时使用`../fonts/...`。

3. **保持页面视觉结构**
   - 不修改原始HTML布局、class、style、文本和组件结构，除非为解决离线兼容性确有必要。
   - 不把`<link rel="stylesheet">`误当成菜单链接处理。
   - 修改链接时只匹配`<a>`标签，绝不能对全文件的`href=`做全局替换。
   - 修改后检查CSS link仍指向本地`.css`文件。

4. **处理离线运行问题**
   - 页面需要静态展示时，移除会导致本地404、路由跳转或外部API报错的Nuxt/SPA脚本 bundle，保留SSR生成的HTML和CSS。
   - 如果必须保留脚本，增加最小化的错误抑制逻辑，拦截网络错误提示，但不要拦截本地CSS、JS、图片和字体资源。
   - 不要用`<base href="/">`覆盖直接打开文件时的`<base href=".">`；这会导致`file://`资源解析到磁盘根目录。
   - 需要HTTP服务器测试时，可以仅在HTTP协议下处理路由，但最终file协议必须保持相对资源路径。

5. **禁用菜单跳转**
   - 用户明确要求禁用跳转时，只处理菜单和页面内`<a>`标签：将目标改为`javascript:void(0)`或移除href并添加`onclick="return false;"`。
   - 不得修改`<link>`、`<script>`、`<img>`、CSS `url(...)`或其他资源引用。
   - 修改后统计：真实`http/https`的`a[href]`应为0；CSS link数量与修改前一致。

6. **自测验收**
   - 启动临时HTTP服务器测试页面，必要时也检查直接打开文件的资源路径逻辑。
   - 检查页面标题、页面高度、关键导航、侧边栏、筛选区、商品表格、图片数量和分页。
   - 检查`document.styleSheets`数量与CSS引用，检查`document.fonts`中关键字体状态为`loaded`。
   - 检查页面不存在404文案、白屏、网络异常弹窗和真实菜单跳转。
   - 检查浏览器控制台与网络请求，区分无关的第三方统计/风控报错和会影响页面展示的错误。
   - 截图超时不能作为成功依据；必须使用DOM、字体状态、资源引用和页面内容多重验证。

## 修改安全规则

- 每次编辑前读取最新文件。
- 不使用全局`href=`替换。
- 不覆盖用户已确认正常的HTML，除非先备份或从原始文件重新合并全部已确认修复。
- 修改后立即检查文件大小、CSS数量、字体引用和关键内容。
- 发现样式变差时优先检查：CSS link是否被改写、`base`标签是否改变、字体路径是否出现多余点号或错误根路径。

## 验收标准

只有同时满足以下条件才报告完成：

- 页面主体结构和视觉样式保持原页面效果。
- 所有关键图片、CSS和字体资源可本地加载。
- `element-icons`与自定义`iconfont`状态为loaded，不出现白色方块图标。
- 菜单按要求不发生外部跳转。
- 没有404页面、网络异常提示或关键控制台错误。
- 已完成浏览器自测并能说明实际检查结果。
